# Getting Started

TPC is built around a simple idea: **the application owns the state; TPC turns that state into presence.**

## 1. Build TPC

The main project is a CMake-based C++ project.

```powershell
cmake -S . -B build
cmake --build build --config Release
```

The resulting runtime is:

```text
build\Release\tpc.exe
```

## 2. Define a target

A target describes how TPC should identify an application and what runtime information it can provide.

Example:

```json
{
  "application": "fl_studio",
  "title": "FL Studio",
  "provider": "fl_studio",
  "process": "FL64.exe"
}
```

Target files are intentionally data-driven so application support does not have to be hard-coded into the presence presentation.

## 3. Choose a launch layer

TPC can launch different presence layers:

```text
upc   Unchanted Presence Client
rpc   RPC layer
fpc   Future/feature presence layer
ppc   Presence presentation layer
```

The exact layer can evolve independently from target detection.

## 4. Connect an application

The connector is selected with `--app`.

For example:

```powershell
tpc --launch upc --app discord --target fl_studio.json
```

The Discord connector can consume the presence generated by the runtime without requiring the target application to know anything about Discord.

## 5. Run and inspect

A typical TPC session reports the detected target, provider, process, PID, and window.

```text
+----------------------------------------+
| running Text Presence.                 |
|----------------------------------------|
| FL Studio                              |
|                                        |
| fl_studio                              |
| Provider: fl_studio                    |
| Process: FL64.exe                      |
| PID: 20640                             |
| Window: FL Studio 2026                 |
|                                        |
+----------------------------------------+
 Target: fl_studio  |  Ctrl+C to exit
```
